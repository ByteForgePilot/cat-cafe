## 数据库设计

### 表结构（6 张表）

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| user | 用户 | userType: 0=顾客, 1=管理员 |
| catinformation | 猫咪信息 | status: 0=休息中, 1=在岗中 |
| product | 商品 | category: 0=服务 1=餐饮 2=猫咪用品, status: 0=下架 1=在售 |
| orders | 订单 | batchNo 批次号, orderStatus 五态, 用户名手机号快照 |
| comment | 评论 | targetType: 0=商品 1=猫咪, auditStatus: 0=待审核 1=已通过 2=已拒绝 |
| likes | 点赞 | likeType: 0=商品 1=评论 2=猫咪, 联合唯一索引防重复点赞 |

### 相对原始设计的结构变更

- **product 表 — 新增字段**
  - 新增 `status TINYINT`
  - 原因：支持上架(1) / 下架(0)。有历史订单时不能直接删商品，先下架隐藏

- **orders 表 — 新增字段**
  - 新增 `batchNo VARCHAR(32)`
  - 原因：多商品下单时同一批次共用，支持聚合展示、批量取消/支付

- **comment 表 — 字段替换**
  - 删除 `catid`，替换为 `targetType` + `targetId`
  - 原因：一张表同时评猫咪(targetType=1)和商品(targetType=0)，和 likes 设计统一

- **comment 表 — 移除约束**
  - 移除外键 `FK → catinformation`，改为软引用
  - 原因：targetId 可能指向 product 或 catinformation，无法建单一外键

## 后端环境搭建

### 技术栈

| 项目 | 版本/说明 |
|------|-----------|
| Python | 3.13.0|
| 虚拟环境 | venv（位于 `backend/.venv/`） |
| Web 框架 | FastAPI 0.115.6 |
| 服务器 | Uvicorn 0.34.0 |
| ORM | SQLAlchemy 2.0.36 |
| MySQL 驱动 | PyMySQL 1.1.1 |
| 数据校验 | Pydantic 2.10.5（FastAPI 自带） |
| 环境变量 | python-dotenv 1.0.1 |

### 调用链

```
浏览器请求 → Uvicorn → FastAPI → SQLAlchemy → PyMySQL → MySQL
```

### 后端文件结构

```
backend/
├── .venv/              # 虚拟环境（不上传 Git）
├── .env                # 数据库密码等敏感信息（不上传 Git）
├── requirements.txt    # 依赖清单
├── config.py           # 读取 .env，拼接数据库连接字符串
└── database.py         # 创建数据库引擎和会话工厂
```

### 各文件作用

- **`.env`** — 存五条配置（数据库地址、端口、用户名、密码、库名）。写在这里而不是代码里，被 `.gitignore` 排除，不会泄露到 GitHub

- **`config.py`** — 用 `python-dotenv` 读取 `.env` 文件内容，拼接出标准格式的数据库连接字符串 `mysql+pymysql://root:yang@localhost:3306/cat_cafe`，供 `database.py` 使用。

- **`database.py`** — 核心连接模块：
  - `engine`：全局唯一的数据库引擎（连接池），程序启动时创建
  - `SessionLocal`：会话工厂，每次请求"取号"拿一个新会话
  - `Base`：ORM 基类，6 张表的模型类都继承它
  - `get_db()`：FastAPI 依赖注入函数——请求进来时创建会话，结束时自动关闭
