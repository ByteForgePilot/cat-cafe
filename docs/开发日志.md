## 数据库设计

### 表结构（6 张表）

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| user | 用户 | userType: 0=顾客, 1=管理员 |
| catinformation | 猫咪信息 | status: 0=休息中, 1=在岗中 |
| product | 商品 | category: 0=服务 1=餐饮 2=猫咪用品, status: 0=下架 1=在售 |
| orders | 订单 | batchNo 批次号, orderStatus 五态, 用户名手机号快照 |
| comment | 评论 | targetType: 0=商品 1=猫咪, auditStatus: 0=待审核 1=已通过 2=已拒绝 |
| likes | 点赞 | likeType: 0=商品 1=评论 2=猫咪, 联合唯一索引防重复点赞 |

### 相对原始设计的结构变更

- **product 表 — 新增字段**
  - 新增 `status TINYINT`
  - 原因：支持上架(1) / 下架(0)。有历史订单时不能直接删商品，先下架隐藏

- **orders 表 — 新增字段**
  - 新增 `batchNo VARCHAR(32)`
  - 原因：多商品下单时同一批次共用，支持聚合展示、批量取消/支付

- **comment 表 — 字段替换**
  - 删除 `catid`，替换为 `targetType` + `targetId`
  - 原因：一张表同时评猫咪(targetType=1)和商品(targetType=0)，和 likes 设计统一

- **comment 表 — 移除约束**
  - 移除外键 `FK → catinformation`，改为软引用
  - 原因：targetId 可能指向 product 或 catinformation，无法建单一外键
